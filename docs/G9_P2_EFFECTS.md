# G9 P2 — Authored on-action effects through world authority

**Issue:** [#138](https://github.com/MohamedXIV/ghostrank/issues/138). This is a narrow executable proof of the *real* event → typed, finite rule → deterministic world job → effect/blocked response pathway. It is **not** the entire P4 opportunity engine.

- **Real producer:** the existing CommandBus `acceptContract` commits `ContractAccepted`; `scheduleContentOnAction` binds its real issuer/contract/minute and can schedule a follow-up only once.
- **Finite rule registry:** `BROKER_RECONCILIATION_RULE_ID` in `src/game/content/effects.ts`, strict Zod-validated effect arguments. The author may NOT submit code or an arbitrary state-write path. This one demonstration spends five points of an existing issuer→player grudge to gain two trust after **420 world minutes**. The actor, accepted contract, original minute, relationship and available grudge are rechecked at execution time; a missing/wrong issuer or insufficient grudge is a blocked, recorded no-op. No credits, rank gating or arbitrary NPC knowledge.
- **Explicit activation:** default worlds have **no** `WorldState.content` field, so all pre-P2 runs stay behaviorally unchanged. A future authored pack may activate IDs in `content.activeRuleIds`; tests use opt-in fixtures. This demo does not silently change current contract economics or grant a new unpreviewed player action.
- **Time and authority:** `content-response` is a world-owned job with phase **2** (after NPC tick, before builds at exact 360-minute ties). The job is queued in `WorldState.jobQueue` using the ordinary ordering and executed by `world-schedule`, never a browser timer or per-frame scan. Pending source records and resolved receipts persist in `WorldState.content`. Save restore reconstitutes only the pending jobs; duplicates and already-resolved IDs have no effect.
- **Provenance:** the existing relationship system applies the clamped trust/grudge change and emits `RelationshipChanged(causeKind:"content",causeId:reactionId)`; the scheduler also emits a developer-facing `ContentReactionResolved` with blocked reason and source ID. **Do not project this authority event to player UI** without explicit redaction.
- **Boundary:** terminal state makes scheduling and resolution no-ops, and the WorldState terminal snapshot is not revived by `reconcileSchedule`. No hidden facts are disclosed; the effect only acts on a contract issuer who actually accepted the player.
- **Non-goals:** P3 migrates one actual objective; P4 activates gameplay-authored opportunities and independent world events. No Ink, Web Worker, Rust/WASM, generalized script VM or redesign of existing economy.

Tests in `src/game/content/on-actions.test.ts` cover real CommandBus acceptance, wrong issuer, resource insufficiency, duplicated source/resolution, split vs bulk wait across 360-minute boundaries, save/reload, no default-world drift, current-run terminality and provenance. Node24 full test/typecheck/lint/build plus existing browser CI must be green before merge. Human novice playtest remains **NOT RUN**.
