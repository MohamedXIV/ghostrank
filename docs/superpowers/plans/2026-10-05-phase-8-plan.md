# Phase 8 — Content Alpha

Issue: #26  
Dependency: Phase 7 / #25 complete.  
Platform policy: web-first; desktop hardening remains deferred to #19.

## Goal

Expand content breadth on top of the finished Phase 2–7 systems without
creating parallel mechanics, rank gates, or content-specific exceptions in the
simulation core.

Repeated runs should expose meaningfully different targets, peers, contracts,
locations, markets and social situations while continuing to use the same
commands, evidence boundaries, economy, world time, threat systems, endings and
persistence contract.

## Grounded starting point

At Phase 8 kickoff the live repository has:

- **5 underground peers** in the canonical world fixture;
- **1 operation target** (NIGHTSHADE) with 2 machines / 2 services;
- contract objectives: **recon-report** and **intrusion**;
- content catalogs already data-driven for:
  - hardware: 6 entries;
  - housing: 4;
  - machines: 5;
  - models: 5;
  - player tools: 3;
  - software licenses: 3;
  - buildable workflow specs: 3;
- no dedicated local balance-telemetry harness.

The largest structural content bottleneck is therefore target/NPC world content:
it still lives directly in `slice-world.ts`.

## Slice order

### P0 — Data-driven world-content roster

Move the existing peer/target/infrastructure definitions into a typed content
module, keep archetype metadata outside authoritative state, validate authored
structural mistakes, and preserve the default world byte-for-byte.

### P1 — Local balance telemetry baseline (delivered, D045)

Run the real CommandBus across 32 fixed seeds, four deterministic player
policies and a 30-world-day horizon. Report run length, ending causes, economy,
rank movement, contract traffic, compromise/veteran pressure, threat activity
and content exposure. The first canonical report is descriptive rather than a
balance threshold: contractor ends ARRESTED in 28/32 seeds, career-exit reaches
RETIRED in 20/32, and idle remains mechanically quiet while the autonomous
world continues. Local command: `npm run telemetry:balance`.

### P2 — Target + NPC breadth (delivered, D046)

Expand the authored roster to 10 peers / 6 targets / 14 target machines / 17
services with fictional scam, extortion, predatory-market, corporate and rival
target-owner pairs. All entries reuse existing actor
skill/defense/discretion/activity/network, target infrastructure and operation
rules. Archetypes remain editorial-only; no target level, rank gate, new command
or threat mechanic ships. P1 telemetry confirms all six targets and all ten
actors are reachable and records the higher ecosystem activity for P6
calibration rather than hiding it with a P2 retune.

### P3 — Contract breadth (delivered, D047)

Expand the existing two objectives to four simulation predicates:
`recon-report`, `infrastructure-map`, `quiet-recon`, and `intrusion`.
Machine/service evidence and recon/intrusive traces remain the only completion
facts; accept/decline/deliver, expiry, ledger payout, trust and reputation use
the existing path. No mission script, new player verb, target level or rank gate
is introduced.

### P4 — Location + physical-life breadth (delivered, D048)

Expand housing from four to eight authored listings. Four new quiet/hidden
workspace/residential combinations reuse the existing lease id, derived
presence, symmetric relocation minutes, daily upkeep, capability fold and
anonymity-based physical-retaliation counterplay. Existing listings remain
unchanged; safehouses remain capability-zero; no rank gate, new command/event,
state field, RNG stream or migration is added.

### P5 — Market breadth

Broaden tools, machines, models, software and workflow content through the
existing capability/economy/contention/authoring rules.

### P6 — Social/event breadth + alpha calibration

Broaden authored forum, rumor and world-event situations, then use P1 telemetry
to tune repeated-run diversity and pacing without weakening established
invariants.

## Global invariants

- content never turns rank into power or access;
- no target exposes a universal difficulty/level requirement;
- archetype labels are authoring metadata, not simulation classes;
- player-facing information keeps the established epistemic boundary;
- new content routes through existing typed commands/events/projections;
- authored data is cloned before simulation mutation;
- invalid content references fail loudly in tests/startup rather than silently
  producing partial worlds;
- real-world exploit/evasion procedures remain fictionalized;
- persistence stores simulation state, not editorial catalog metadata;
- default Phase 2–7 behavior stays stable unless a later breadth slice
  intentionally changes the canonical roster and updates its evidence.

## Exit criteria

- repeated runs encounter meaningfully different targets, contracts, tools,
  locations and social situations;
- content is data-driven where practical;
- no content path bypasses canonical command/simulation/persistence boundaries;
- local telemetry can measure run length, endings, economy, ranking movement,
  content exposure and major causes of failure.
