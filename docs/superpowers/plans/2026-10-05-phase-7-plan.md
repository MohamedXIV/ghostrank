# Phase 7 — Endings and Long-Run Systems

Issue: #25  
Dependency: Phase 6 / #24 complete.  
Platform policy: web-first; desktop/Tauri history reconciliation remains #19.

## Goal

Make survival, deciding when to stop, and leaving the underground meaningful
goals independent of reaching rank #1.

Phase 7 owns the boundary Phase 6 intentionally refused to cross: terminal
state, ending eligibility, voluntary retirement, completed-run history, veteran
pressure, and bounded late-game capability.

## Grounded starting point

At Phase 7 kickoff the repository already had:

- Phase 6 investigations, probes, physical retaliation, safehouses, compromise
  conditions, and player-safe postmortems;
- deterministic world time and one fixed ecosystem tick;
- one browser active-run save slot;
- no terminal record;
- no `RunEnded`;
- no completed-run history.

P0 established the missing terminal substrate before any eligibility policy.

## Slice order

### P0 — Terminal run contract (delivered, D037 / #41)

One `WorldState.ending` record, one idempotent `endRun`, one `RunEnded`
event, one terminal command guard, canonical persistence, safe final projection,
and an in-world final screen. P0 adds no ending trigger.

### P1 — Consequence-driven forced endings (delivered, D038 / #42)

Consume only current Phase 6 causal conditions. Identity exposure branches by
history into ARRESTED / UNMASKED / MISSING; STRANDED uses P4's explicit resource
floor; generic COMPROMISED requires same-boundary rig + dwelling loss. A
terminal boundary freezes the current world-time command immediately.

### P2 — Exit plan as a playable operation (delivered, D039 / #43)

Retirement is now PLAN → visible wind-down → COMMIT → cooling → derived READY.
The wind-down reads only player-visible state: no active operation, accepted
contract, in-flight build, running model, active software, or lease. A blocked
commit costs no time; a clean commit spends 60 world minutes through the normal
danger chronology, then freezes a two-day cooling deadline. During cooling the
player can wait, read messages, or cancel and return to normal play. READY is
derived from clock truth and P2 emits no ending; P3 classifies the final outcome
from actual history. No rank or hidden threat state participates, and the whole
mechanic remains fictionalized rather than a real evasion procedure.

### P3 — Retirement outcomes and VANISHED (delivered, D040)

READY closes only through the explicit finish action, then D037 records RETIRED
or VANISHED. Classification reads completed contracts by issuer network plus
existing reputation/consequence history; it never reads player rank or the
starting White/Black package. VANISHED is deliberately narrow (three White
completions, no Black completions, no Opportunist/Predator history, no
catastrophic compromise, no social unmasking). All other READY runs can still
retire with a structured White/Black/mixed closing tone. P3 adds no new roll and
no duplicate persisted alignment field.

### P4 — Completed-run history (delivered, D041 / #45)

Browser IndexedDB v2 adds a `run-history` store and atomically moves the
canonical terminal portable state out of the active slot. Archive failure falls
back to the terminal active snapshot so a reload cannot revive play; boot
recovery retries the move, and a later boot creates a fresh active run
separately after success. History stores final authoritative state once;
`deriveCompletedRunSummary` reconstructs safe ending/tone, final economy and
activity counts, descriptors, and P5 postmortems on demand. GHOST/OS exposes a
read-only History app newest-first. Closed PR #40 supplied only the storage
pattern; its competing `run.status` terminal model remains superseded. Native
SQLite history parity stays deferred to #19.

### P5 — Exceptional long-run pressure (delivered, D042 / #46)

P5 is a strict no-op before two world weeks, and age alone never raises
difficulty. After that gate, existing causal history derives a bounded
ORDINARY / KNOWN / ENTANGLED / VETERAN band from completed or missed work,
intrusive escalation, surfaced authority evidence, retaliation, probes,
physical threats and compromises. The band may raise contract traffic and the
attempt probability of already-valid probe/physical routes, but it cannot create
grudge, physical backing, prior-probe provenance, investigation material, a
veteran tax, or any rank gate. Pressure is recomputed at each ecosystem tick so
whole/split waits remain equivalent. Only band + broad causal reasons project;
numeric score/bonuses remain internal and no authoritative P5 field is stored.

### P6 — Limited exotic / quantum capability

Late, rare, bounded content using the existing capability model. It must not
erase ordinary constraints or become a mandatory rank ladder / universal
success button.

## Global invariants

- rank is reputation/visibility, never ending power;
- one run ends at most once;
- every ending cites authoritative causal provenance;
- commands cannot mutate a terminal run;
- if an ending happens inside a time command, the clock stops at that exact
  ending boundary and no later same-tick/tail work runs;
- ending presentation cannot leak hidden truth beyond the established
  player-safe epistemic boundary;
- completed history derives summaries from final authoritative state rather than
  duplicated mutable counters;
- legacy saves remain valid under explicit compatibility rules;
- browser is the normal gameplay release gate;
- no real networking, exploit execution, host-code execution, credential theft,
  or real-world evasion procedures.

## Phase exit criteria

- surviving and leaving is meaningful without reaching rank #1;
- multiple forced endings arise from deterministic causal history;
- voluntary retirement is a playable process;
- a rare peaceful White VANISHED path exists;
- Black retirement can succeed with distinct context/tone;
- completed runs remain browsable with safe postmortem context;
- long survival becomes harder for causal reasons;
- exotic capability remains late and bounded.
