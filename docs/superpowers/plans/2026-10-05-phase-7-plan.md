# Phase 7 — Endings and Long-Run Systems

Issue: #25  
Dependency: Phase 6 / #24 complete.  
Platform rule: web-first; Tauri/SQLite history reconciliation remains #19 / Phase 10.

## Goal

Make survival, choosing when to stop, and leaving the underground meaningful
goals independent of reaching rank #1.

Phase 7 owns the boundary Phase 6 deliberately refused to cross: terminal run
state, ending eligibility, voluntary retirement, completed-run history, and
long-run pressure.

## Grounding from the shipped repository

Phase 6 already provides:

- concrete catastrophic conditions with causal provenance;
- investigations, rival probes, physical threats, relocation and safehouses;
- P5 player-safe postmortems derived from hidden provenance;
- deterministic world time and fixed ecosystem ticks;
- a web-first active-run save in IndexedDB;
- no `RunEnded`, no terminal flag, and no completed-run archive before this
  phase.

The current browser persistence had only one `active-run` slot. SQLite already
has a `runs.status` column but desktop hosting is explicitly deferred. P0 must
therefore establish the lifecycle/history boundary before any ending policy.

## Slice order

### P0 — Run lifecycle + completed-run archive (D037)

- one authoritative `active | ended` lifecycle record;
- one idempotent `RunEnded` boundary;
- every simulation command terminal after ending;
- safe projection of kind/label/minute only;
- minimal terminal shell;
- browser IndexedDB completed-run archive storing the full final validated state;
- boot recovery for a terminal active snapshot;
- no ending eligibility yet.

### P1 — Consequence-driven forced endings

Consume existing Phase 6 truth to decide a bounded first set of forced endings.
Map only conditions that can be justified by existing causal state; do not invent
captured/killed/arrested mechanics where the simulation has no corresponding
condition yet. Add any missing authority/physical terminal condition as an
explicit causal rule before mapping it to `endRun`.

### P2 — Exit plan as a playable operation

Retirement is not a menu button. Build a fictionalized, multi-step wind-down
using existing economy/relationship/location vocabulary: obligations,
infrastructure, dangerous relationships, identity abandonment, and a cooling
period. No real-world evasion instructions.

### P3 — Retirement outcomes and VANISHED

Derive retirement variants from actual run history/context rather than a morality
meter. White/Black identity influences tone and relationships but never hard-locks
actions. The rare peaceful White `VANISHED` ending must be earned by a coherent
history, not one checkbox; Black retirement gets distinct tone/variants.

### P4 — Completed-run history surface

Browse archived final states and derive summaries/postmortems from them. The
archive stores truth once; UI summaries remain projections. Include days survived,
final/peak data only where truth exists, value moved, major operations,
compromises, relationships/descriptors, and final cause/status.

### P5 — Exceptional long-run pressure

Make very long survival increasingly difficult through causal world pressure,
not rank scaling or arbitrary hidden difficulty. Prefer accumulated relationships,
attention, obligations, infrastructure exposure, and world reactions.

### P6 — Limited exotic / quantum capability

Late, rare, bounded capability/content. It must not erase ordinary constraints,
become a mandatory rank ladder, or turn the simulation into fantasy omnipotence.

## Global invariants

- rank is never power and never an ending trigger by itself;
- one run ends at most once;
- every ending has an authoritative cause id;
- commands cannot mutate a terminal run;
- ending presentation cannot leak hidden truth beyond P5's epistemic boundary;
- completed-run history is derived from final authoritative state, not duplicated
  counters where truth already exists;
- save/load preserves terminality;
- browser is the gameplay release gate;
- no real networking, exploit execution, malware, credential theft, or real-world
  evasion procedures.

## Phase exit criteria

- surviving and leaving is meaningful without reaching rank #1;
- multiple endings arise from deterministic causal history;
- voluntary retirement is a playable process;
- a rare peaceful White VANISHED path exists;
- Black retirement can succeed with materially different tone;
- completed runs are browsable with safe postmortem context;
- long survival becomes harder for causal reasons;
- exotic capability remains late and bounded.

## Verification

Each slice must keep the normal gates green:

- simulation/component tests;
- typecheck;
- lint;
- static production web build.

Ending slices additionally require:

- terminality tests;
- save/load tests across ending boundaries;
- projection leak tests;
- deterministic seeded scenarios for each eligibility rule;
- history derivation tests against archived final states.

## Out of scope

- desktop packaging or SQLite run-history parity before #19;
- multiplayer;
- host-code execution;
- real network targets;
- real-world identity/evasion procedures;
- replacing the existing P5 postmortem with an omniscient report.
