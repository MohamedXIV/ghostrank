# Phase 6 — Run Threat and Physical Consequences (Kickoff Plan)

Issue: #24 (unblocked by the closure of #23 — Phase 5, 2026-10-04)
Builds on: the whole Phase 3–5 stack. The substrate this phase must reuse rather
than re-invent is concrete and already named in code: traces + causal footprint
(`world.traces`, `world.reactions`, `VisibleFootprint`), grudge and retaliation
(`UndergroundState.retaliations`, `retaliate()`), the unmasking taboo
(`punishUnmasker`/`condemnUnmasking`), rumors/inbox (`underground.rumors`,
`.messages`), forums (`.forumPosts`), relationship stances
(`relationshipStance` → `friendly|neutral|wary|hostile`), the deadline-tick
pattern (`advanceUpkeep` → `advanceBuilds` → `advanceUnderground`, all folded in
`CommandBus.advanceWorldTime`), the instance-id scheme (`kind:N`, max-suffix for
property), `hashUnit(seed, ...parts)` as the only randomness, and the value
graph (`deriveValueGraph` as the precedent for a pure derived read).

## Why this plan starts here (actual repo state)

Verified against the tree at `96e3a08`, not against the docs' description of it:

- **Threat is currently social only.** The worst a rival can do today is a smear
  (player rank −1%, grudge threshold 30, 12%/tick) or an unmasking (−5%,
  threshold 60, 3%/tick, ecosystem turns on the unmasker) —
  `systems/underground.ts:59-68`. Nothing crosses into the physical world, and
  nothing can end a run.
- **There is no run-ending machinery at all.** No `RunEnded` event type, no
  alive/compromised/run-over flag anywhere in `src`. The event union
  (`events/types.ts`) ends at `WorldTimeAdvanced`. So "catastrophic compromise"
  is greenfield — and the boundary with Phase 7 (#25, which owns the endings)
  has to be drawn explicitly, because there is no existing terminal state to
  extend.
- **The physical layer is a stub, and thinner than the docs imply.**
  `src/game/phaser/types.ts` is 10 lines: `RoomPresentation { locationId,
  avatarPosition, worldMinute }` — declared and **referenced nowhere else in
  `src`**, so nothing feeds it — and `PhysicalIntent = { type: "wait"; minutes }`
  — the only intent, and `bridge.ts`'s `physicalIntentToCommand` is pure
  (type-only import, no bus access), so it cannot decide anything even by
  accident. The room scene (`room-surface.tsx`) builds a `Phaser.Game` with no
  bus wired in and only ever calls `onUseDesk`, a React view switch. The names
  `MoveToDesk`, `LeaveLocation`, `VehicleArrived`, `LocationAbandoned` in
  `AGENTS.md` and `docs/TECHNICAL_ARCHITECTURE.md` are prose intent, not code.
  The room HUD hardcodes `SHORT-TERM ROOM // UNIT 04` (`room-surface.tsx:155`)
  and its "something red outside the window" cue is a cosmetic tween, not a
  simulation signal. Phase 6 is where this stops being decoration.
- **"Where you live" is already modelled, as money.** `economy.housing` is a
  nullable lease id over `src/content/housing-catalog.ts` (`housing-cowork-loft`,
  `housing-rented-lab`), billed at day boundaries by `advanceUpkeep`, and an
  unpayable boundary already *moves the player out* to the free baseline
  (`upkeep.ts:48-73`). A parallel "current location" field would be a second
  source of truth for the same fact and would desync. Physical presence must
  **derive from the lease**; safehouses extend it, they don't duplicate it.
- **The no-single-Heat-bar rule is already honoured.** `VisibleFootprint`
  carries a *band* (`none|low|elevated|severe`), and stances/retaliations are
  names and kinds, not numbers — `project-world.ts:215-249`. Threat can grow
  inside that discipline instead of replacing it.
- **Determinism tooling is sufficient and must not be widened.** Every ecosystem
  roll is `hashUnit(seed, purpose, tickIndex, actorId, ...)`; the 360-minute tick
  (`TICK_MINUTES`) and 28-tick catch-up cap (`MAX_CATCHUP_TICKS`) are the frozen
  clocks this phase inherits. No RNG state, no `Math.random`.

## The Phase 5 handoffs (kept explicit so they cannot be lost)

Closing #23 recorded two things as deliberately *not* done in Phase 5, each
pinning a slice here. As with #22's two handoffs, every slice review must
re-confirm these are still on-map; neither may slide into "later polish".

1. **"AI uses automation to watch THE PLAYER."** `docs/AI_SYSTEMS.md` lists it
   under "NPC use"; the machinery shipped in P4 is NPC-vs-NPC only, and the
   deferral is written down twice — `2026-10-04-phase-5-marketplace.md` ("*use
   AI against you* is Phase 6 (#24) territory by the roadmap's own shape") and
   D030 ("player-facing AI automation (watching *you*) is deliberately Phase 6
   (#24) threat drama"). → Satisfied by **P2 — rival probes**, which re-reads
   the *same* `npcAssistDeltas` from the attacker's seat against the player, so
   there is no second rulebook (D030's own "one function, both seats" line
   extended to the third seat).
2. **Build interruption.** `2026-10-04-phase-5-build-system.md` deferred it
   precisely: "they cannot re-roll or re-time a job; **whether they can pause
   the queue at all waits for Phase 6 threats**". → **Satisfied by P3 / D034.**
   Extending `dueWorldMinute` was rejected because that is still a re-time.
   `startedWorldMinute`, `dueWorldMinute`, model/spec identity, and the frozen
   outcome stay immutable. Interruption is separate optional pause state
   (`pausedAtWorldMinute` + `accumulatedPausedMinutes`), and completion derives
   as frozen due + closed pause time. An active pause has no completion boundary.
   This is the same commissioned job with elapsed outage time kept outside its
   frozen clock, including save/restore and builds started during an outage.

Two further inherited obligations this phase picks up rather than leaves:

3. **Lease loss as a scripted threat.** D021 closed with "per-day billing at a
   lease's first partial day, rival landlords, and **lease loss as a scripted
   threat** remain open for later phases." The lapse-on-unpayable path already
   exists; being *evicted by events* does not. → **P4**, explicitly moved there
   by D034: changing the lease inside P3 would couple retaliation to later upkeep
   boundaries inside the same wait and belongs with catastrophic compromise's
   durable chronology.
4. **Physical presence is real but thin.** WORLD_RUNS_AND_ENDINGS names the
   signal list (strange vehicle, footsteps, a knock, unknown call, door-camera
   motion, outage, unusual connectivity, unexpected delivery) and the rule "the
   game should avoid explicit countdown warnings when ambiguity is more
   effective". GAME_DESIGN adds "Threat should rarely be summarized by one
   visible Heat percentage. The player instead receives evidence." → **P1 and
   P3** ship the signals; the room renderer only *displays* them.

## Handoff TO Phase 7 (#25) — the boundary that must not be blurred

Phase 6 produces **conditions and causes**; Phase 7 produces **endings**. There
is no existing terminal state to extend, so the split is drawn by contract:

- Phase 6 owns: investigation progress, probes, physical warnings, retaliation
  escalation, relocation/safehouses, and **catastrophic compromise as a durable
  state condition** with a citable cause chain.
- Phase 7 owns: `RunEnded`, the arrested/unmasked/missing/compromised ending
  *renders*, run history, voluntary exit, and the VANISHED/retirement branches.
- Consequence, stated so it can't be crossed by accident: if a P4 slice reaches
  a point where a run *should* be over, it emits the compromising events and sets
  the condition, and the player's rig keeps answering — the run-end screen is
  not built here. If that turns out to be unplayable rather than merely
  incomplete, the fix is a *new* decision (D03x), not a silent Phase 7 steal.

## Core rules this phase must not break

- **Rank never gates and is never power.** Rank and footprint may raise an
  actor's *visibility* — who thinks you're worth the cost of probing — and that
  is the design's own "indirectly increases danger" line. It must never enter a
  danger *outcome* formula as a stat, never make an NPC "too strong to attack",
  and never block a relocation, safehouse, or action.
- **Lift-never-punishment does not mean consequences are banned.** The standing
  rule is that a penalty slides *a bonus* toward its no-bonus baseline and never
  below it. Threat is a different category: physical events can genuinely destroy
  property, because loss of the thing is the design's point. What stays frozen is
  the *capability* floor — an outage may stop helping (like contention, like a
  lapse) and may cost time or goods, but it can never push an action below the
  no-hardware baseline. P3 must test that line explicitly rather than assume it.
- **Credits never go negative; no debt.** Relocation and safehouse costs are
  one-time debits on the P5/P7 property template, or daily upkeep on the
  D021/D022 lapse template. An unpayable eviction already exists; an unpayable
  relocation is a rejected command that mutates nothing.
- **Hidden truth persists, never projects** (D028/D030). An investigator's
  actual evidence quality, a prober's actual read, and a roll's outcome stay in
  the simulation. The player receives signals with provenance. A test pins the
  projected key set and JSON-scans for the hidden-truth number names.
- **No explicit countdown.** An investigation deadline is not surfaced as
  "3 days left". Deadlines that are *player-facing by nature* (contracts already
  have `expiresWorldMinute`) stay visible; threat deadlines do not.
- **Terminal/GUI parity, per verb**, and the Phaser bridge stays contracts-only:
  it may submit `moveTo`/`leave` intents and render events; it decides nothing.
- **Zero-regression**: every new `WorldState` field is optional-or-identity and
  legacy-defaulted, so the 476 tests / 49 files at the tip re-run byte-identical
  in a default world. The only honest test edits are counts a growing catalog
  forces.

## Slice map (sequential, each verified + documented + PR'd + merge-committed)

**P0 — Physical presence: location derives from the lease.** The room becomes a
read of simulation truth instead of a caption. New content
(`src/content/safehouse-catalog.ts`) with anonymity/relocation attributes and a
cost shape on the existing property-or-rent templates; new `PhysicalIntent`
verbs (`moveTo`, `leave`) and a fed `RoomPresentation`; the room HUD's hardcoded
label replaced by projection. **No `locationId` state field** — presence is
derived from `economy.housing` + the player's chosen fallback, so there is one
source of truth. Adds the first physical commands (`move`, `safehouse <verb>`)
shared by Terminal and GUI, costing world time through the existing
`advanceTime` path. *(Exit contribution: relocation exists as a real, timed
choice before any threat needs it.)*

**P1 — Authority investigation as a deadline-driven read.** A new
`investigations` array on `WorldState` (optional, legacy-`[]`) advanced by one
more fold in `advanceWorldTime`, riding the `advanceUpkeep`/`advanceBuilds`/
`advanceUnderground` pattern so it is split-invariant and save-safe by the same
proof. Progress accumulates from the causal footprint the player already emits
(`traces`, `reactions[].footprintScore`, retaliation provenance) — never from a
fresh roll against a hidden difficulty score, and never from rank as a stat. It
surfaces as *evidence*: an unusual login, a changed marketplace response, a
missing contact — routed through the existing rumors/inbox/feed surfaces rather
than a new panel with a bar. **Deliberately not the ending**: it produces an
`InvestigationAdvanced`-class event with citable source ids.

**P2 — Rival probes: automation aimed at the player** *(handoff #1)*. Peers
spend their tick probing the player using the same `npcAssistDeltas` primitive
already read from the offence and defence seats, so AI-assisted probers make
AI-assisted mistakes in the same math. A probe lifts *the prober's* knowledge of
the player's infrastructure standing (hidden truth, persisted, unprojected) and
leaks a signal the player can observe; a player who lays low, changes relays, or
relocates raises the odds the read is wrong. Tests must prove rank is not an
input, that an unprobed world re-runs byte-identical, and that a probe never
gates a target or an action.

**P3 — Retaliation goes physical** *(delivered; handoff #2, D034)*. Extends
the grudge ladder below the unmasking taboo: a rival with enough grudge, existing
Black-network physical backing, and a prior P2 probe can produce ambiguous
outside evidence, an outage, or a property hit. Rank is not an input; P0
anonymity and P1 investigation pressure are. Probe correctness remains real, so
a wrong read can lead to the wrong kind of action rather than becoming
omniscience. Build interruption is true pause/resume with frozen
`startedWorldMinute` / `dueWorldMinute` / outcome untouched; exact-boundary
ordering lets an outage beat a build due on the same tick. A property hit may
destroy owned hardware while baseline play remains available. The active lease
is deliberately untouched here and its scripted loss moves to P4. This slice
also lands D030's event-layer beat: a peer in a non-warning escalation may
deterministically acquire an assistant and then uses the same existing NPC AI
math on later ticks.

**P4 — Catastrophic compromise as a durable condition.** The state where the
handle, an identity, the rig, or the current dwelling is lost *enough to
matter*: recorded with cause provenance, surviving save/restore, visible in the
projection as names and kinds, and never as an ending screen (Phase 7 boundary).
Includes the eviction-by-event path D021 left open and the "broke / stranded"
condition the endings doc lists, expressed as a state the player can act on.

**P5 — Postmortem causal chain: a pure derived read.** The
`docs/GAME_DESIGN.md` example chain (day 2 reused relay → day 4 correlated
signatures → day 6 handle sold → day 8 payment traced → day 9 arrest) built the
way `deriveValueGraph` was built: a fold over events and provenance ids that
already exist, **zero new state, zero new commands**. The substrate is already
citable — `OperationTrace.id`, `OpponentReaction.sourceTraceIds`,
`UndergroundRumor.sourceId/relayId`, `UndergroundRetaliation.id` as a cause id,
ledger `cause:{kind,id}` — which is why this is a read and not a recorder. It
does not reveal hidden truth (D028's leak rule holds on the postmortem too: it
shows what the player could have known, not the seed), and it is what makes the
third exit criterion testable.

## Exit-criterion plan (how each becomes a checked fact, not a vibe)

- *Early runs are genuinely dangerous*: P1+P2+P3 must make a documented, seeded
  reckless sequence (escalate, reuse a relay, keep escalating on a watching
  target) reach a physical consequence within a few days, proven by a scenario
  test, not by tuning claims.
- *First-time survival around a few days is plausible*: a measured, disengaging
  sequence must survive days 3–10 with a balance-test harness that samples many
  seeds and reports the run-length/cause distribution
  (`docs/TESTING_STRATEGY.md` already asks for exactly this statistic). This is
  the only exit criterion that needs a *measurement*, so it gets the harness in
  the slice that can produce it (P4), and the number is reported honestly even
  when it's inconvenient.
- *Players can usually learn something concrete from failure*: P5's chain is
  asserted to contain at least one citable player-side mistake per compromise,
  with a test that a failure with no player-caused trace produces "no chain",
  not a fabricated one.

## Out of scope (recorded, not silently dropped)

- **Endings and the exit plan** — #25 / Phase 7, per the boundary section above.
  Phase 6 sets conditions; it does not render a run-over screen.
- **Open-world movement, avatar animation set, art** — AGENTS.md scope control;
  the physical slice stays rooms with contextual transitions. `avatarPosition`
  stays a presentation string, not simulation truth.
- **Proficiency** — still deferred until playtesting earns it (the standing
  rule since the Phase 5 kickoff).
- **True multi-hop NPC↔NPC value chains** (D024) and **NPC cloud/rent economics**
  (P4's note) — inter-actor credit flows are still not a thing; a threat slice
  that needs them should say so rather than fabricate edges.
- **A vram-bearing lease** (D027's "lab with accelerators is a content beat") —
  Phase 8 breadth.
- **Provider-behaviour drama** (refusal / rate limit / logs reaching an
  investigator): genuinely tempting here, but it is `docs/AI_SYSTEMS.md` cloud
  *risk* content and belongs to a provider-behaviour slice, not smuggled in as a
  threat mechanic. Recorded so it isn't lost.
- **Multiplayer, real network access, host-code execution** — permanently out.
