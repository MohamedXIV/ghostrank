**Status: P0–P7 merged; P8 verified complete in the canonical branch; PR creation pending. Parent: #27.**

Phase 9 turns the Content Alpha into a stable, visually legible, feature-complete web beta. It does not add a new gameplay architecture.

Canonical interface direction: `docs/INTERFACE_AND_DISTROS.md`.

## P5 — New-run, save, migration + recovery hardening *(delivered; #62 / PR #71)*

Close the browser lifecycle gaps before beta.

Deliver:
- explicit new-run flow,
- real run seed variation without exposing it as a power choice,
- representative historical-save fixtures,
- migration tests,
- refresh/crash recovery behavior,
- corrupt/incompatible save messaging,
- active-run/history edge-case hardening.

Exit:
- representative historical saves either migrate safely or fail readably,
- reload/crash cannot revive terminal runs or silently destroy active progress,
- repeated new runs are not all the fixed alpha seed.

Delivered:
- explicit no-run/new-run lifecycle: empty durable storage no longer creates a run automatically.
- fresh runs receive varied non-zero 32-bit seeds while remaining deterministic after seed selection; legacy fixed seed remains only for deterministic fixtures.
- typed save diagnostics distinguish corrupt JSON, unsupported format/version and schema-validation failures.
- representative historical save fixtures cover early Phase 2/3, Phase 4/5 economy, Phase 6 threats/presence and Phase 7 endings.
- corrupt browser saves are inspected non-destructively and can be archived before starting fresh.
- fresh-run replacement awaits the previous session flush before writing the new active slot; GameShell cleanup tracks the current session so refresh/unmount does not miss pending persistence.
- persistence initialization failure returns to an explicit no-run/volatile mode rather than silently starting a run.
- terminal snapshots stay terminal across recovery and completed history survives new runs.

## P6 — Beta balance + telemetry follow-ups *(delivered; #63 / PR #72)*

Use measured policies rather than tuning by impression.

Add coverage for the known Phase 8 gaps:
- purchasing/market affordability policy,
- pressure-band reachability,
- seed-varied new runs,
- novice/low-knowledge behavior where useful,
- run length/endings/economy/rank/failure distributions after UI/onboarding changes.

Exit:
- market affordability is measured before price changes,
- `known`/`entangled` pressure bands are either justified/reachable or deliberately redesigned,
- no rank gate is introduced.

Delivered:
- multi-seed telemetry expanded to 6 realistic play styles: `idle`, `cautious-novice`, `contractor`, `reckless`, `rig-builder`, and `career-exit` across 32 varied non-zero seeds (`CANONICAL_BETA_VARIED_SEEDS`, 192 total runs).
- purchasing and affordability telemetry (`rig-builder`): measures hardware, housing, software, local models, and player-authored tool acquisitions, tracking expenditure (~3,375–11,535 credits, median ~6,998 cr), timing (hardware day 2.4, housing day 3.0, tools day 11.0, models day 11.7), wallet pressure, and clean upkeep lapses (~22%) without destructive negative debt.
- pressure-band reachability root cause identified and validated: `LONG_RUN_PRESSURE_START_MINUTES` requires 14 days; across the canonical varied-seed matrix, pacing-aware `cautious-novice` runs reached `known` in 25/32 runs (78.1%) and `entangled` in 31/32 runs (96.9%) without needing arbitrary mechanic tweaks.
- zero rank or power gates introduced; deterministic simulation preserved under all seeds.
- comprehensive empirical report and findings documented in `docs/BETA_BALANCE_TELEMETRY.md`.
- final local verification at `1ebf947f24babbee3251113386880ff017cdedb7`: 95 test files / 854 tests passing, clean typecheck, clean production build, lint clean (only pre-existing PostCSS warning). ## Cross-cutting rules

- Rank remains reputation, never power.
- Terminal and GUI use the same commands/capabilities.
- UI animation never owns simulation time.
- Presentation does not enter deterministic simulation output.
- Distros/themes are cosmetic.
- Visualizations may not expose hidden authoritative truth.
- Prefer local verification over GitHub Actions when hosted CI is unnecessary.
