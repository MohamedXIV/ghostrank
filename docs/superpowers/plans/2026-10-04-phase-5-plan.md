## Why this plan starts here (actual repo state)

- The five capability axes are **not** all live. `compute`, `memory`, and
  `network` are consumed — speed (P1) and breadth (P2). **`vram` and `storage`
  are summed by the hardware and machine catalogs but read by nothing.** They
  are the designed landing point for Phase 5: "more VRAM allows larger/faster
  local AI models", "storage affects archives/models/backups"
  (`docs/ECONOMY_PROGRESSION_AND_SKILLS.md`). *(Now live: P1 contention made
  them consumers — see `2026-10-04-phase-5-contention.md`.)*
- There is **no AI, model, workflow, IR, or build concept anywhere in `src`**.
  This phase is greenfield on top of a stable, deterministic substrate.
- `PlayerState` is `{ handle, rank }` only — there is **no proficiency system**.
  The design sketches one, but #23's deliverables do not require it; proficiency
  is explicitly deferred (see Out of scope) so Phase 5 does not smuggle in a
  stat the exit criteria never ask for.
- `advanceUpkeep` is the single recurring-cost authority at world-day
  boundaries; cloud subscriptions are the natural first consumer to add there.

## Core rules this phase must not break (from #23)

- AI operates entirely inside the simulation; **no real model calls, no host
  code**. Generated software is validated virtual data / workflow IR.
- Stronger models + hardware raise throughput/quality but **remain fallible** —
  AI can misclassify, hallucinate a relationship, overstate confidence, or emit
  a defective workflow. Determinism is preserved by seeding outcomes, never RNG.
- Local/cloud tradeoffs consume simulated resources, time, money, or
  availability — never a hard gate (a skilled player with modest gear still
  attempts any target).
- Software creation **reuses the same capability system** as purchased tools;
  no parallel effect model.
- Credits never go negative; a base state with no model active is exact
  identity, so every pre-Phase-5 test passes untouched (the standing
  zero-regression pattern).

## Slice map (sequential, each verified + documented + committed)

**P0 — AI substrate and model catalog.** `src/content/model-catalog.ts` of
named models (fictional), each with a source (`cloud` | `local`), properties
(reasoning / coding / context / reliability / speed / footprint), a cost shape
(cloud = recurring subscription; local = one-time acquisition + hardware
footprint), and an effect expressed in the existing `SoftwareEffect` terms.
New state: an `economy` slot for the active model choice + owned local models;
legacy saves default to **no model active = identity**. One command to
select/rent a model shared by Terminal + GUI. Ledger gains a model cause kind.
This slice adds the *choice*, not yet contention.
*(Delivered as `2026-10-04-phase-5-models.md`; the property seed landed as
three bands — reasoning / context / reliability — consumed by no one until
P2/P3, and the command trio is buy/run/stop. **P2 consumed them** as the
analysis drivers (context/reliability for claims, reasoning+context for
confidence); P3 inherits the same semantics for build quality.)*

**P1 — Compute contention; vram/storage become live.** The transferred
criterion #2 slice. A running local model / active build reserves `vram`
(and `storage` for archives/queues); while reserved, a time-sensitive operation
draws on less of the pool, so it slows (acceleration reduced, never below the
P1 one-minute floor). Rented/secondary compute relieves it; the player can
pause a build, drop model quality, or accept slower execution. Turns the two
dead axes into real, deterministic decisions — still never a gate.
*(Delivered as `2026-10-04-phase-5-contention.md`; realized as pure derived
physics rather than reservation state — no footprint is "held", the pool
simply delivers less of the model's own shortcut the hungrier the rig is, and
pause/drop-quality are the already-shipped stop/run/switch choices.)*

**P2 — AI analysis.** A selected model augments recon: it can propose
machine/service classifications or correlations as *evidence-shaped* output with
provenance and confidence, **and can be wrong** (deterministic, seeded). Expert
play = verify important conclusions. Reads existing evidence; adds no gate.
*(Delivered as `2026-10-04-phase-5-analysis.md`; the plan's
"evidence-shaped output" was realized as its opposite in one respect — claims
are explicitly **not** evidence and never join the evidence ledger, and their
hidden subject/accuracy never project, because predicting not-yet-recon'd
structure is the only thing the assistant can usefully do (restating observed
facts would be a redundant second source). It is instant (contract precedent)
and requires a running model — its function, not a gate on anything else.)*

**P3 — Software specification UI + virtual workflow/IR build system +
build/tests/defects.** The transferred criterion #1 slice. The player specifies
intent/inputs/outputs/permissions/tests (not host source); the model turns the
spec into a validated **workflow/IR** (a safe data structure) over in-game
**build time** (function of model capability, compute, complexity — reusing the
P1 duration math). Builds finish with success / warnings / failed tests /
defects (deterministic). A finished workflow registers as an owned capability
**through the same `SoftwareEffect` runtime**, so a self-built tool folds into
`effectiveCapability` exactly like a purchased one — closing the *author* half
of "buy, use, author, sell" and satisfying #23's "replace at least one premium
workflow with a self-built alternative".
*(Delivered as `2026-10-04-phase-5-build-system.md`. Commissioning moves zero
credits — a build is priced in world time and rig occupancy, not money. Both
the duration and the quality roll are frozen at commissioning, so a build is
split-invariant (the same spec always lands at the same minute regardless of
how the wait is chunked) and an "interruption" is a consequence of freezing,
not a new mechanic. In-flight jobs project with no outcome — the projection
never contains "clean"/"warnings"/"defective" until completion — while an
owned workflow projects fully, because it is the player's own ground truth.
The spec's payoff is a plain `SoftwareEffect` folded through the same
combinators as licenses and tools, so there is no second effect system to
drift.)*

**P4 — Model/tool marketplace and NPC AI use.** Models/tools authored and sold
in-fiction (P5 provenance template), and NPCs *use* models in the deterministic
ecosystem (activity, watching, AI-assisted mistakes) — "AI is part of the
ecosystem, not a player-exclusive superpower" (`docs/AI_SYSTEMS.md`).
*(Delivered as `2026-10-04-phase-5-marketplace.md`, closing the phase. One
pure function reads `UndergroundActor.modelId` on the existing tick: a
reliable read lifts the actor's offence, a miss costs skill *and* discretion,
so an AI-assisted mistake surfaces in the public feed — and the same function
read from the defender's seat is the peer's "automation to watch". No model
is exact `{0, 0}`, so every unmodelled world re-ran byte-identical. On the
market side, `ModelListing.author` routes an authored purchase's debit to a
named peer in the value graph — the P5 tool template, reused, no new commands
or cause kinds. The projection shows *that* a peer runs an assistant
(`assistants`: handle + model label + author only), never the lift: hidden
power stays hidden ground truth, D028's rule at ecosystem scale.)*

## Invariants to test (established pattern, per slice)

- empty/no-model state is exact identity: the 354 pre-Phase-5 tests pass
  untouched (the same zero-regression discipline that held every Phase 4 slice);
- determinism: identical runs agree; contention slow-downs are functions of
  state, not clock or order; chunked waits are split-invariant for cloud billing;
- credits never go negative (subscription/lapse semantics reuse the license
  all-or-nothing pattern: an unpayable subscription lapses the model, no debt);
- generated IR is validated data — the schema rejects anything that is not a
  well-formed workflow (never free-form code);
- AI conclusions carry provenance and can be proven wrong in a test;
- Terminal/GUI parity: every new command parses to the same typed command the
  GUI helper emits.

## Out of scope (deferred, stated plainly)

- The **proficiency** model (Unfamiliar→Expert bands, learning-from-activity):
  design sketch exists, no #23 exit criterion requires it; it needs its own
  evidence from playtesting before it becomes a slice. Deferred rather than
  half-built.
- Quantum capability (rare late-game resource), the broader crypto-like asset
  classes (liquidity/volatility/exchange friction), and true multi-hop
  NPC↔NPC value graphs (still waiting on inter-actor credit flows, per D024).
- Physical rack footprint / power-heat as a constraint layer.
- Any real model integration or host-code execution — permanently out of scope.
